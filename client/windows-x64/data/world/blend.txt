# How a model mesh is blended. Nothing in the .bmd says it - the int16 that
# looks like a render mode, BmdMesh::texture, only repeats the mesh's own index
# in all 1294 models - so it is data, and changing it costs no recompile.
#
# main.exe has two inputs, both found by disassembling RenderMesh (0x00440D50).
#
# 1. The texture's component count: the TGA loader writes 4 (0x00529EB4), the
#    JPEG loader writes 3 (0x00529A54), and 0x00441064 alpha-blends whatever
#    has 4 - so every .tga a .bmd names is blended there, with the alpha test
#    of glAlphaFunc(GL_GREATER, 0.25) on top. Applying that wholesale here
#    bleaches the foliage instead of softening it, because our .ozt alphas sit
#    mostly between 0.25 and 1 where the original clearly does not, so the .tga
#    meshes that need it are listed one by one below until that is understood.
#
# 2. OBJECT.BlendMesh (+0x64), a mesh index the CreateObject switch at
#    0x004FF85D assigns per world and per object type; RenderMesh (0x00440FED)
#    draws the matching mesh with glBlendFunc(ONE,ONE) and the depth mask off
#    (0x00511710), and BlendMesh <= -2 means the whole model. The index is
#    resolved to the texture that mesh carries, because this renderer is
#    handed a .bmd and never learns the object type.
#
# Only Lorencia is transcribed. The other worlds have their own tables at
# 0x004FFC20 (world 2), 0x004FFC90 (world 3), and two more for 7 and 8.
#
# Format: <key> <opaque|alpha|additive>, where <key> is <model.smd>:<texture>,
# or a bare <model.smd> for every mesh of it, or a bare texture name. The
# model name is the authoring path the .bmd stores for itself, which is what
# tells House03 from HouseWall02 - the file name is nowhere in the .bmd.

# PoseBox01: the handler at 0x004FF99C sets the field to -2, and RenderMesh
# takes the "<= -2" branch for every mesh, so the whole model is additive.
# Its only texture is 2x2 pure black, which is how a marker stays invisible.
pose_box.smd                           additive
